1. Overview and core principles

Codex Advisor is an open-source, skills-only plugin integrated with Codex CLI and Codex desktop.

  • Local integration. The plugin runs from your own Codex installation. It has no Zero Delta-hosted service or remote backend; bounded consultation packets are sent through your authenticated Codex/OpenAI account.
  • No Zero Delta relay. Consultation packets are sent directly through your authenticated Codex/OpenAI account. Zero Delta receives no packets, runs no proxy, and collects no telemetry.
  • No telemetry or analytics. The plugin includes no telemetry, no analytics tracking, no crash reporting, and no MCP server.
  • Read-only, zero-tool child. Advisor child processes run in a forced read-only sandbox with no tools enabled. They cannot make tool calls or modify local files; the Codex runtime still sends the bounded consultation packet directly to OpenAI through your authenticated account.

2. Data categories, purposes, and recipients

Advisor handles a small, explicit set of data. This section names each category, its purpose, and who receives it.

  • Consultation packet and response, sent to OpenAI. When the root agent invokes a consultation, it compiles a bounded technical packet containing the decision question and the code context, architectural options, and repository boundaries it chose to supply. The packet is transmitted to OpenAI for inference through your authenticated account and allowance; OpenAI returns the response to your local Codex runtime. Consultations are locally launched, not locally inferred: inference is performed by OpenAI, not on your machine. The packet is not intended to carry credentials, secrets, personal data, or unrelated conversation history.
  • Zero Delta receives no packets. Advisor has no relay, proxy, or telemetry backend. Zero Delta never receives consultation packets or responses.
  • OpenAI retention and controls. How long OpenAI retains consultation packets and responses is governed by your OpenAI account agreements and the account controls OpenAI provides, described in OpenAI's privacy policy. Advisor does not invent or enforce a separate retention period on OpenAI's behalf.

3. Local data and retention

  • Codex session logs. Consultation activity, receipts (ADVISOR CALL and ADVISOR RESULT), and decisions are recorded locally within your persisted Codex session logs, for example ~/.codex/sessions. They remain until you delete them or your host's own retention removes them. The plugin never uploads, copies, or shares persisted Codex session logs.
  • Configuration and catalog. The live advisor.toml bundled with the installed plugin controls the configured Standard and Specialist models and effort. Advanced settings and model-catalog data may be stored under your Codex home directory. These local files persist until you delete them.
  • Optional usage journal. The optional content-free usage journal is disabled by default. If enabled, it stores operational metadata and aggregate usage counters only — model identifiers, timestamps, and counters — and stores no consultation packets and no response content. Later journal writes prune entries older than 30 days and enforce a bounded count; there is no background deletion service.
  • Private consultation captures. Per-consultation captures are removed by the launcher's unconditional cleanup on normal exit; an abnormal stop may leave temporary files behind under your Codex home directory, and you can delete them yourself.
  • Model routing. Automatic Standard remains Terra/high for ordinary bounded architecture, interface, data-model, and generic-advisor decisions. Automatic Specialist remains GPT-6.1 Sol/high only when targeted evidence still leaves an eligible cross-system, compatibility/concurrency, competing-diagnosis, security/trust, recovery, irreversible-migration, or data-loss decision unresolved. The separate advisor-astra role is explicit-only, uses Astra/high, and is never selected automatically.

4. Authentication and credentials

Codex Advisor relies exclusively on your existing local Codex host authentication. The plugin does not request, collect, store, transmit, or handle OpenAI API keys or login credentials, and it does not read or duplicate credential files from your environment.

5. This website

This site is a set of static pages served from Zero Delta LLC's own hosting. It sets no cookies, loads no third-party scripts or fonts, and runs no analytics or tracking. The hosting provider Opalstack keeps standard web server access logs — the IP address, timestamp, requested path, and user agent of each request — which are processed by Opalstack and Zero Delta for security and operational purposes. The provider's standard log rotation retains these logs for about seven days, as documented for applications at docs.opalstack.com/user-guide/applications/ and for staff usage at community.opalstack.com/d/92-usage-check. Provider backup retention is separate and controlled by the provider.

6. Voluntary support email

If you email advisor@zerodelta.dev, Zero Delta and its email provider receive your name, email address, message, and any redacted diagnostics you choose to include, for the purpose of providing support. This correspondence is retained while your request is being handled and for any necessary follow-up or legal obligation. Advisor itself never sends email; contacting Zero Delta is always your choice. To request access to or deletion of your support correspondence, contact advisor@zerodelta.dev.

7. User control and data deletion

You can inspect, modify, archive, or delete local user state with standard operating system tools: Codex session logs, configuration and catalog files, and the optional journal (via journal clear and journal disable). For data held by OpenAI, use the controls of your OpenAI account. Uninstalling the plugin may leave user state and session logs behind; those are managed separately and can be removed by you.
