1. Overview and core principles

Codex Advisor is an open-source, skills-only plugin integrated with Codex CLI and Codex desktop.

  • Local integration. The plugin runs from your own Codex installation. It has no Zero Delta-hosted service or remote backend; bounded consultation packets are sent through your authenticated Codex/OpenAI account.
  • No Zero Delta relay. Consultation packets are sent directly through your authenticated Codex/OpenAI account. Zero Delta receives no packets, runs no proxy, and collects no telemetry.
  • No telemetry or analytics. The plugin includes no telemetry, no analytics tracking, no crash reporting, and no MCP server.
  • Read-only, zero-tool child. Advisor child processes run in a forced read-only sandbox with no tools enabled. They cannot make tool calls or modify local files; the Codex runtime still sends the bounded consultation packet directly to OpenAI through your authenticated account.

2. Information handled by the plugin

Local consultation context

When the root agent invokes a consultation, it compiles a bounded five-section packet containing the technical decision question, and the relevant code context, architectural options, and repository boundaries that the root agent chose to supply. The packet is not intended to carry credentials, secrets, personal data, or unrelated conversation history.

That packet is processed locally by your authenticated Codex runtime through your existing OpenAI subscription. Communication with OpenAI is governed by your own OpenAI account agreement and OpenAI's privacy policy. Codex Advisor interposes no proxy, no intermediate server, and no hosted service.

Local session data

  • Consultation activity, receipts (ADVISOR CALL and ADVISOR RESULT), and decisions are recorded locally within your persisted Codex session logs.
  • Those logs remain on your own storage under your configured Codex home directory, for example ~/.codex/sessions.
  • The plugin never uploads, copies, or shares persisted Codex session logs.

3. Configuration and optional usage data

The live advisor.toml file is bundled with the installed plugin and controls the configured Standard and Specialist models and effort. Advanced settings and model-catalog data may be stored under your Codex home directory. These local files are separate from the consultation packet sent through your authenticated account.

  • The optional content-free usage journal is disabled by default.
  • If enabled, it stores operational metadata and aggregate usage counters only. It stores no consultation packets and no response content.
  • Later journal writes prune entries older than 30 days and enforce a bounded count. There is no background deletion service.
  • Automatic Standard remains Terra/high and automatic Specialist remains Sol/high. The separate advisor-astra role is explicit-only, uses Astra/high, is never selected automatically, uses more Codex allowance, and remains subject to account and runtime availability.

4. Authentication and credentials

Codex Advisor relies exclusively on your existing local Codex host authentication. The plugin does not request, collect, store, transmit, or handle OpenAI API keys or login credentials, and it does not read or duplicate credential files from your environment.

5. Third-party services and surfaces

  • OpenAI Codex. Consultation requests execute via your local Codex installation. Standard remains Terra/high, Specialist remains Sol/high, and the separate explicit-only advisor-astra role uses Astra/high subject to account and runtime availability. Data handling by OpenAI is governed by OpenAI's terms.
  • No MCP or hosted service. Codex Advisor provides no MCP server, no hosted service, and no background cloud service.

6. User control and data deletion

Consultation receipts and decisions may remain in your local persisted Codex session logs, while live plugin configuration and optional journal or catalog state are managed separately under the installed plugin and your Codex home directory. You may inspect, modify, archive, or delete that user state using standard operating system tools. Uninstalling the plugin may leave user state and session logs behind; those are managed separately and can be removed by you.
