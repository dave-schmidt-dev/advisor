1. Support channels

For bug reports and feature questions, the GitHub issue tracker is the primary channel — it keeps the discussion public and searchable for the next person hitting the same thing. Use advisor@zerodelta.dev for anything you would rather not file publicly.

Codex Advisor is an open-source project maintained on a best-effort basis. There is no response-time commitment.

2. Supported platforms and scope

Supported

  • Codex CLI on macOS and Linux.
  • Codex desktop on macOS and Linux, with persisted sessions.

Out of scope

  • Generic ChatGPT alone. With no local Codex runtime, preflight emits route: unavailable.
  • Remote and hosted services. The plugin operates with no MCP server and no hosted service; neither is supported.
  • Native Codex subagents as a consultation transport. They inherit parent permissions and cannot supply the required read-only isolation guarantee.

3. Prerequisites checklist

Work through this before opening a ticket. Most route: unavailable reports resolve here.

  1. Codex CLI or Codex desktop is installed and operational.
  2. jq is installed and on your $PATH — check with which jq.
  3. You have a /bin/sh-compliant POSIX shell.
  4. An active persisted Codex session rollout exists in your Codex home directory.
  5. CODEX_THREAD_ID is set in the active parent execution context.
  6. The escalated launcher permission (require_escalated) is enabled for the installed plugin launcher script.
  7. Your subscription has model availability for gpt-5.6-terra and gpt-5.6-sol.

4. Common scenarios

A. Preflight returns route: unavailable

Symptom. The root agent emits:

ADVISOR DECISION
route: unavailable

Cause. inspect-parent-runtime.sh could not verify the parent environment or a prerequisite.

Remedies. Confirm jq is installed and reachable. Confirm you are in an interactive, persisted Codex session — ephemeral test sessions have no persisted rollout and correctly emit route: unavailable. Confirm the companion scripts were installed via install-agents.sh.

B. Model availability or authorization failure

Symptom. The consultation launcher reports a failure or an unexpected model response.

Cause. Your OpenAI account lacks model availability for gpt-5.6-terra or gpt-5.6-sol.

Remedies. Verify your subscription tier includes those models at high reasoning effort, and verify Codex authentication with the standard CLI commands.

C. Response classification retry

Symptom. Stderr shows a single retry during consultation.

Behavior. This is by design. A runtime-valid first child whose response is empty or structurally malformed gets exactly one fresh retry. If the retry also fails, the plugin records recommendation: unavailable and decision: blocked and stops. Packet, launcher, identity, runtime, wrong-model, wrong-effort, and tool-use failures are terminal and never retry.

5. Diagnostic commands

Verify a local installation without starting Codex or making a network call:

sh plugins/advisor/scripts/verify.sh --static

Review aggregate local consultation activity. This redacts code, prompts, filenames, paths, and identifiers:

sh plugins/advisor/scripts/advisor-audit.sh --window-hours 24

6. Submitting a report

Include these four things. Without them, the first reply is going to be a request for them.

  1. Codex host type (CLI or desktop) and version.
  2. Operating system and shell version.
  3. The output of sh plugins/advisor/scripts/verify.sh --static.
  4. The relevant ADVISOR DECISION, ADVISOR CALL, or ADVISOR RESULT receipts from the conversation.

Redact secrets and proprietary context before sending. Receipts are written into your conversation, so check what you are pasting.
